# Cheatsheet

Every command in this repo, deduplicated. Rules and conventions live in `AGENTS.md`; this file
is just the runnable surface. See `context/ai-interaction.md` for what the agent may run
without asking, and `data/README.md` before consuming any JSON.

## Data layer

Run from the repo root. The binary is `python3`.

```sh
python3 scripts/extract.py      # fetch raw ESPN responses (skips existing; --force refetches)
python3 scripts/normalize.py    # data/raw/ + data/manual/ -> data/processed/ (every year, always)
python3 scripts/validate.py     # invariant checks over data/processed/; non-zero exit on failure
ruff check scripts/ && ruff format scripts/
```

Two traps:

- **`normalize.py` has no `--years` flag, deliberately.** A partial run truncates every
  processed file to the listed years while leaving `box_scores/` intact. Full-archive runs only.
- **Always run `validate.py` after `normalize.py`.** Its warnings are documented data quirks;
  a *new* warning means something changed.

### Per-tenant imports (the product path)

`data/manual/` is hand-curated for the record-book league, so a different league resolves
zero owners. The import pipeline generates its own manual directory from that league's ESPN
records instead:

```sh
python3 scripts/test_derive_owner_map.py   # identity-derivation self-check

python3 scripts/derive_owner_map.py \
  --raw-dir data/tenants/<id>/raw \
  --out-dir data/tenants/<id>/manual        # owner map + empty stubs for every other manual file

python3 scripts/normalize_for_import.py \
  --raw-dir data/tenants/<id>/raw \
  --out-dir data/tenants/<id>/processed \
  --manual-dir data/tenants/<id>/manual     # unmodified normalize.py + validate.py
```

`scripts/crawl_from_env.py` runs all three plus the R2 upload and the D1 status update;
`scripts/run_import.mjs` is the Node entry point that reads credentials out of D1. Both
`normalize_for_import.py` and `crawl_from_env.py` need `--manual-dir`/`derive_owner_map.py`
to have run first — they fail loudly rather than silently falling back to `data/manual/`.

`data/tenants/` and `data/raw/` are gitignored: a tenant archive is real people's data.

## App

Run from `app/`. `sync-data.mjs` (copying `data/processed/` → `app/public/data/`) runs
automatically before `dev`, `test`, and `build`.

```sh
npm run dev          # vite
npm run build        # sync-data + tsc -b + vite build
npm test             # sync-data + vitest run
npm run lint         # oxlint
npm run format       # prettier --write .
npm run format:check # prettier --check .
```

Typecheck alone:

```sh
cd app && npx tsc -b --noEmit
```

There is **no root tsconfig** and no root `node_modules`, so `tsc` has to run from `app/`.
Plain `tsc --noEmit` checks nothing and passes vacuously. Plain `-b` skips up-to-date
projects — add `--force` if results look stale.

`tsc -b` builds three projects from `app/tsconfig.json`:

| Project | Covers |
| --- | --- |
| `tsconfig.app.json` | `src/` — the Vite/React browser app |
| `tsconfig.node.json` | `vite.config.ts` |
| `tsconfig.functions.json` | `functions/` (Pages Functions) plus the shared `lib/` |

`functions/` and `lib/` depend on `Env`, which only `app/worker-configuration.d.ts`
declares — it is generated by `wrangler types` from the bindings in `app/wrangler.jsonc`
and **is committed**. After adding, renaming, or removing a D1/R2/secret binding:

```sh
cd app && npx wrangler types   # regenerates worker-configuration.d.ts — commit it
```

Without it, every handler fails with `Cannot find name 'Env'`.

Never edit `app/public/data/` directly; it is a build artifact.

## Hooks

```sh
node scripts/hooks/check-changed-file.mjs <file>   # credential scan + ruff on .py
node scripts/hooks/protect-raw-data.mjs <path>    # exits non-zero under data/raw|data/audit
```

`check-changed-file.mjs` is advisory (`--strict` also fails on credential findings).
`protect-raw-data.mjs` is a hard block.

Enable the pre-commit gate once per clone:

```sh
git config core.hooksPath .githooks
```
