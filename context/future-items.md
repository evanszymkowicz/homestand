## Non-blocking, carried from the S5 review

| Item | Why |
|---|---|
| ~~Rate-limit `login`, `reset-request`, `probe`~~ | **Done 2026-10-05, superseded 2026-10-06.** These three originally charged Cloudflare's native `ratelimits` binding. That binding **cannot be declared in a Pages config** — `wrangler pages deploy` rejects the whole file — so it was removed along with `functions/lib/rateLimit.ts`; the D1 horizon limiter below is now the only rate limiter, and it is strictly stronger (10-minute through daily windows vs the binding's 10/60s). |
| `reset-request` response-time oracle | The body is already constant (`{ok:true}` either way), but an unknown address skips both the D1 insert and the outbound email, so timing still distinguishes it from a real account. Deliberately not fixed: making it constant-time means doing that work unconditionally, i.e. emailing addresses that do not exist. Fix it when Resend lands, since that adds a real network call to the gap. |
| Retention countdown banner | `imports.expires_at` is now written (free tier +30d, migration `0005_import_expiry.sql`) and enforced by the data proxy (`410`). Nothing surfaces the countdown to the user yet — the landing page advertises "30-day access". |
| Gate the league switcher to subscriber tier | The `<select>` renders for any account with more than one completed import. Free tier is clamped to 1 import server-side, so this is currently unreachable, but the UI does not enforce it. |
| ~~Per-import R2 prefix for the processed archive~~ | **Done 2026-10-05.** Keys are now `processed/{importId}/…`; `upload-r2.mjs` writes the demo dataset under `processed/demo-import/` and `crawl_from_env.py` writes each tenant's own prefix. Two tenants' bytes are isolated at the storage layer, not just by the D1 ownership check. |
| ~~Per-league owner resolution~~ | **Done 2026-10-05.** `scripts/derive_owner_map.py` builds a league's owner map from its own ESPN `members[]` + `teams[].owners[]`, unioning SWID renames and same-name account changes, and stubs every other manual file empty so no league inherits this league's answers. Verified against the real 18-season archive: 30 owners / 180 team-seasons, identical to the hand-curated map, and `validate.py` reports **0 failures across 30 checks** (was 27). Two related fixes went with it: the fork's own `owner-map.json` stored canonical *names* where the schema wants owner_id *slugs* (all 180 entries corrected), and `validate.main()` hardcoded `Path("data/raw")` instead of reading its own `RAW_DIR` global. |
| ~~Proxy-served manual files~~ | **Done 2026-10-05.** `retired-owners.json`, `jersey-history-overrides.json` and `position-overrides.json` are allowlisted in `app/lib/collections.ts` but live in `data/manual/`, not `data/processed/`, so they 404'd for **every** tenant including the demo. Both the crawl and `upload-r2.mjs` now publish them alongside the processed output. |
| ~~Resend email provider~~ | **Done 2026-10-06**, as Gmail SMTP rather than Resend — no domain required, at the cost of sending as a personal address. `functions/lib/email.ts` keeps the stub's contract (best-effort, never blocks auth, never logs message bodies) and no longer logs bodies at all. `api/admin/invites` was deleted with the invite gate; signup is email + password, verified then approved. |
| ~~`cron` trigger for TTL eviction~~ | **Done 2026-10-06.** `cron/` is a standalone Worker on `17 * * * *` (Pages has no scheduled handler). It POSTs to `api/admin/evict` with `ADMIN_API_KEY` and prunes `rate_limit_counters`. The opportunistic prune in `rateLimitHorizon.ts` was removed — one mechanism, not two. Deployed; the cron Worker also holds `HOMESTAND_ORIGIN`. |
| Automated crawl trigger (production path) | **Partly done 2026-10-06.** `run_import.mjs` now takes `--target local\|remote` (default local, so nothing accidental reaches production) and `--pending` to sweep every queued import; both it and `crawl_from_env.py` honour `ESPN_TARGET` for every D1/R2 call, so a production run is no longer silently local. Each import is claimed with `status = 'running'` before the crawl starts, and `crawl_from_env.py` sets `completed`/`failed` as before. **Still open:** nothing actually hosts the runner — a machine that runs `node scripts/run_import.mjs --pending --target remote` on a schedule (or a GitHub Actions cron) — and there are still no import-status emails. |
| Stack-trace disclosure on 5xx | An unhandled D1 error currently returns a stack with absolute build paths in local dev. Production Pages returns a generic 500, but any future `onError` handler must not regress this. |
| Long-horizon rate limits (D1 counter) | **Done 2026-10-06, now the only limiter.** `functions/lib/rateLimitHorizon.ts` charges fixed 10-minute / hourly / daily windows over D1 (`0009_rate_limit_counters.sql`). Applied to `login` (10/acct/hr, 25/acct/day, 60/ip/hr), `reset-request` (3/address/hr, 5/day), `probe` (5/acct/10min, 20/day), and `signup` (5/ip/hr, 3/address/hr). Fails closed; `Retry-After` is the longest tripped window, not the shortest. It absorbed the native `ratelimits` binding that Pages cannot deploy. **Cost:** every limited request now costs one D1 write. The limits are reasoned guesses, not measurements — revisit against `SELECT bucket, hits FROM rate_limit_counters ORDER BY hits DESC` once there is real traffic. |
| WAF rate limiting rule | Not available today, by topology rather than choice. The account has **no zone** (`GET /zones` returns empty) and the app is served from `homestand.pages.dev`, which Cloudflare operates and which cannot carry a zone-level rule. Needs a custom domain on a real zone **plus** at least Pro: Free gives one rule, Path-only expressions, IP-only counting, and a 10-second window — a tighter ceiling than the D1 horizon limiter already provides, for no per-account keying. Worth it as defense in depth once a domain exists, because it runs before the Worker and costs no D1 write. **Sequencing caveat:** Pages serves `*.pages.dev` and the custom domain simultaneously and cannot disable the former except via Access or an account-level Bulk Redirect, so the rule protects only whichever hostname users actually arrive on. Do not treat "a WAF rule exists" as "the endpoint is rate limited" until that redirect is in place. |
